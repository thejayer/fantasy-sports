# AGENTS.md

## Cursor Cloud specific instructions

This is a dual-product monorepo. See `README.md` (ffa engine) and `HUB.md` (member hub) for standard commands; only non-obvious startup/run caveats are captured here.

- **ffa** — Python NFL analytics engine + Streamlit dashboard (`src/ffa`, CLI `ffa`).
- **Strictly Jayers hub** — Next.js member hub (`apps/web`) plus the ESPN sync CLI `sj` (`src/sj`).

### Python env (venv)
- Dependencies install into a virtualenv at `/workspace/.venv`. The update script creates it and installs from `requirements-lock.txt` then `pip install -e . --no-deps` (CI parity). `/workspace/.venv/bin` is prepended to `PATH` via `~/.bashrc`, so `ffa`, `sj`, `pytest`, and `ruff` work directly in a login shell; otherwise call them as `.venv/bin/<cmd>`.
- The base image ships Python 3.12 without `ensurepip`; `python3.12-venv` was apt-installed during environment setup (captured in the snapshot). If `python3 -m venv` ever fails with an ensurepip error, reinstall it: `sudo apt-get install -y python3.12-venv`.
- After changing deps in `pyproject.toml`, regenerate the lockfile: `uv pip compile pyproject.toml --extra dev --extra dashboard --extra gcs --python-version 3.11 -o requirements-lock.txt` (3.11 floor so the same pins work on CI's 3.11 + 3.12 matrix).

### Lint (ruff)
- CI installs `ruff` from `requirements-lock.txt` and runs `ruff check .`; the code is kept clean under current `ruff` (0.16+). The only lint exemption is `[tool.ruff.lint] ignore = ["B008"]` in `pyproject.toml`, for Typer's documented `x: T = typer.Option(...)` default-argument pattern used by the `ffa`/`sj` CLIs — keep it. Run `ruff check .` for CI parity; if a new `ruff` release flags additional rules, fix the code (or add a narrow, justified `ignore`) rather than pinning `ruff` down.

### Tests
- `pytest` is fully offline (synthetic fixtures) — no `ffa ingest` needed. Run from repo root.

### ffa CLI / dashboard
- Most `ffa` commands (`score`, `project`, `simulate`, `rank`, `optimize`, `draft-sim`, `backtest`, `dashboard`) need ingested data first: `ffa ingest --season 2023 --season 2024` writes Parquet to `data/raw/` (requires network to nflverse via `nflreadpy`). `data/` is gitignored, so re-ingest after a fresh VM. Configs live in `configs/*.yaml`.
- Calibrated level path (roadmap 4.1): pass `--conditioned-level` on `simulate` / `rank` / `optimize` / `draft-sim` / `backtest` to use `LevelModel` with rosters `years_exp` (and per-tier collapse). Global `--level-sd` / `--level-mean` remain the scalar fallback.
- Projection snapshots (roadmap 4.2): `ffa export-projections --season YYYY` writes `{out_dir}/{scoring}/{season}.json` (default `data/sj/projections/`, `--conditioned-level` on by default). Hub reads via `getProjectionSnapshot(scoring, season)` — never invoke `ffa` from Next.js request handlers. Committed fixtures live under `fixtures/sj/projections/`. Nightly producer: `.github/workflows/refresh.yml` → `store/projections/` artifacts (promote into live store separately).
- Weekly posteriors: `ffa export-weekly-projections --season YYYY` writes `{out_dir}/{scoring}/{season}.json` under `weekly_projections/` with `grain: typical_week` (one bootstrapped historical game per sample — not schedule-adjusted). Hub: `getWeeklyProjectionSnapshot` **requires** `grain === "typical_week"` (rejects mis-copied season files). Fixtures under `fixtures/sj/weekly_projections/`.
- Playoff odds: `ffa export-playoff-odds --sj-root data/sj --season YYYY` writes `playoff_odds/{league_id}/{season}.json` (make-playoffs MC over remaining H2H weeks). Needs **live** sj league snapshots + player map + weekly history. Hub: `getPlayoffOddsSnapshot`. Fixtures under `fixtures/sj/playoff_odds/` (regenerated from the MC; standings-locked when no undecided H2H). Nightly refresh **skips** playoff export/promote unless `data/sj` is present — never promote fixture-derived odds to GCS. When live `data/sj` *is* present, export **fails closed** if it writes zero JSON.
- Player map fixtures include `method: fixture_overlay` rows that map a few synthetic hub roster ESPN ids → GSIS so offline trade/strength/start-sit joins are non-empty. Live sync still uses real ESPN ids from `export-player-map`.
- ESPN↔nflverse map (roadmap 4.3): `ffa export-player-map --season YYYY` writes `data/sj/player_map/{season}.json` from `rosters.parquet` (+ optional `--ff-playerids`). Coverage = football hub roster ESPN ids resolved under `--sj-root`. Hub reads via `getPlayerMap(season)`. Use `--fail-below 0.95` in ops when live `data/sj` is present; fixture leagues use synthetic ESPN ids so hub coverage against fixtures alone is near zero — that is expected.
- `ffa dashboard` launches Streamlit (the `[dashboard]` extra is installed) and needs ingested data.

### Hub web app (`apps/web`)
- Run with `npm run dev` (Next.js 16 + Turbopack on `http://localhost:3000`). See `HUB.md` for full setup. Lint is `npm run lint` → `eslint .` (not `next lint`). Keep `src/middleware.ts` for Auth.js Edge — do not rename to `proxy.ts` (Node-only). Snapshot purge uses `revalidateTag(tag, "max")`.
- Frontend tests (roadmap 1.2): `npm test` is Vitest (node for `*.test.ts`, jsdom via pragma for `*.test.tsx` RTL). Playwright: `npm run build` then `npm run test:e2e` (fixture smoke with `AUTH_DEV_BYPASS=1`) and `npm run test:e2e:auth` (login redirect, bypass off, port 3001). E2E forces `SJ_DATA_DIR` to `fixtures/sj` so a local `data/sj` seed cannot flake assertions. Smoke covers leagues list, standings, roster, 404s, projections, tools (playoff-odds / draft slot / waivers / start-sit), ESPN draft results, activity, and baseball Waivers. CI job is `web-e2e`.
- For local dev without Google OAuth, create `apps/web/.env.local` with `AUTH_DEV_BYPASS=1` (plus any `AUTH_SECRET`) to skip login entirely. With bypass off, only `ALLOWED_EMAILS` Google accounts **or** emails in `{SJ_DATA_DIR}/hub_members.json` can sign in.
- **Admin center** (`/admin`): add member emails, set `admin`/`member` role, link one franchise per league from current snapshots. Persist to `{SJ_HUB_DIR}/hub_members.json` (uncached). Bootstrap: until an admin exists, anyone on `ALLOWED_EMAILS` / `ADMIN_EMAILS` can open `/admin`.
- **Hub vs ESPN stores:** Prod Cloud Run mounts one RW GCS bucket at `/app/data/sj` and sets both `SJ_DATA_DIR` and `SJ_HUB_DIR` there (dual FUSE failed PORT probes). Locally, unset `SJ_HUB_DIR` defaults to sibling `data/hub`. `getLeagueIndex` **merges** distinct roots. `sj sync`/`backfill` skip `platform: hub` and refuse to overwrite `sport=golf`.
- League pages render one sport-aware `LeagueView` (`apps/web/src/components/LeagueView.tsx`). Do not reintroduce a football-only branch on `leagues/[leagueId]/page.tsx`. Baseball roster team pages still use `BaseballRosterView`.
- Season chips are the shared `SeasonSwitcher` (`apps/web/src/components/SeasonSwitcher.tsx`) on league and team pages. Pass `hrefFor` so team URLs stay under `/leagues/{id}/teams/{teamId}?season=`.
- Players tab uses client `DataTable` / `PlayersDataTable` (roadmap 3.3). Keep `LeagueView` as a server component; do not pull standings/season chrome into the client bundle. Prefer pagination over new table libraries.
- Matchups tab (`?tab=matchups&view=week|schedule|playoffs&week=N`) uses server `MatchupsPanel` + `lib/matchups.ts` (roadmap 3.4). Pair from parallel `schedule`/`scores`/`outcomes` arrays (bye = opponent id equals self). Box scores are not in the snapshot — do not invent per-player lines.
- Draft results (`?tab=draft&team=`) and Activity (`?tab=activity&view=all|trades|waivers`) read ESPN `league.draft` / `league.transactions` for **both** sports — not the football Tools → Draft Monte Carlo sim. Baseball Waivers (`?tab=waivers`) is a projection-free `FreeAgentsBoard` over `free_agents`; football FA stays under Tools → Waivers (VOR join).
- History tab (`?tab=history&view=standings|champions|records|h2h&a=&b=`) uses `getLeagueHistoryArchive` + `HistoryPanel` / `lib/history.ts` (roadmap 3.5). Loads standings + matchups across seasons only (skip rosters). Key franchises by `team_id`, not owner name. Committed fixtures are usually single-season — use `sj seed` for decade demos; production multi-season needs **Actions → backfill sync** (or `sj backfill` / Cloud Run `--args=backfill`) into the live store, plus hub deploy with the GCS bucket mount.
- Projections (roadmap 4.4): football-only `?tab=projections` (+ optional `&scoring=ppr|standard`) renders `ProjectionsBoard` (season VOR board). Roster + players tables show Floor/Med/Ceil via `lib/projection-join.ts` joining ESPN ids through `getPlayerMap` → `getProjectionSnapshot`. Season snapshots stay season-level — start/sit uses weekly posteriors on the tools tab. Committed football fixtures use synthetic ESPN ids; `player_map` includes `fixture_overlay` rows so a handful of roster cells resolve offline (live sync uses real ESPN ids).
- Decision tools (roadmap 4.5): football `?tab=tools&view=trade|waivers|strength|draft|start-sit|playoff-odds`. Trade syncs `?a=&b=`; Start/Sit uses dedicated `?team=` (not trade `a`). Draft chips come from `listDraftSimSlots` (only on-disk `slot_N.json` files — fixtures often ship 1/6/7/12). Half-PPR leagues fall back to the PPR export (`usesHalfPprScoringFallback`); hub season may resolve to the prior NFL export year (`projectionSeasonCandidates`) — both are disclosed in UI. Waivers prefer synced ESPN `free_agents` (`waiverBoardRows`); fall back to unrostered projections when the season has none. Draft uses offline `ffa export-draft-sim` (`getDraftSimSnapshot` → `DraftBoard`, `?slot=N`). Start/Sit uses `ffa export-weekly-projections` (`getWeeklyProjectionSnapshot` → `StartSitBoard`). Playoff make-odds use `ffa export-playoff-odds` (`getPlayoffOddsSnapshot` → `PlayoffOddsBoard`) — do not dress season/weekly quantile boards as playoff probabilities, and do not call `ffa` from Next handlers.
- Baseball (roadmap 4.6): **projection-free by design.** `BASEBALL_TABS` includes `projections` / `tools` EmptyStates for the NFL-only engine boundary, plus ESPN `waivers` / `draft` / `activity`. Never load projection bundles for baseball (`wantsProjections` stays football-gated). Do not add MLB code to `src/ffa` without a real ingest/calibration plan. See `HUB.md` § Baseball scope.
- Golf (roadmap 6.4a–e + 6.5 + auction/keepers + live room): hub-native via `src/sg` + hub auction room. Fixtures stay snake. Offline create: `snake`/`auction` via `runGolfDraft`. Live create: `run_draft: false` + `POST …/auction` → `auction_room.json` (uncached; tick timers on GET/POST). Actions: `POST …/auction/actions` (`start|nominate|bid|pass|finalize`) with `revision` optimistic concurrency. UI: `AuctionRoomPanel` polls 1s; acting-team selector (no OAuth↔franchise ACL yet). Finalize writes draft/rosters/lineups/scoreboard via `finalizeAuctionRoom`. Keep `lib/golf*.ts` client-safe; room I/O in `golf-auction-store.ts`. `sj sync` skips non-ESPN platforms.
  - Tee-time locks are fail-closed. Use `lineupClock(synced_at)` on **both** the Lineup UI and the POST route (`GOLF_FIXTURE_NOW` when fixture `synced_at` starts with `2026-07-27`) — wall-clock `new Date()` locks every March/April tee time after those dates pass.
  - Snapshot layout may write empty `lineups.json` / `scoreboard.json` shells for ESPN sports, but `assemble_snapshot` must only attach top-level `lineups` / `scoreboard` when the concern has real events/teams (otherwise football/baseball v1 fixture schema checks fail).
  - Scoring lives in `sg.score` / `sg.rounds` (best 4/5 midweek, weekend alts, multiplier, captain TB). Hub only displays the artifact.
  - Next 16 `allowedDevOrigins` includes `127.0.0.1` / `localhost` (`apps/web/next.config.ts`) so cloud Playwright/browser hydration works against either host; prefer `http://localhost:PORT` if client clicks ever look dead.
- Hub Docker image (Phase 5 / AUDIT #17): runtime is **sj-only** — do not reintroduce `pip install -e .` into `apps/web/Dockerfile` (that pulls the ffa analytics stack). Optional startup sync is `python -m sj.cli` with `PYTHONPATH=/app/src`. `images` CI asserts analytics imports are absent.
- Deploy (roadmap 1.3): hub/sync/dashboard workflows use Workload Identity Federation (`permissions.id-token: write` + `google-github-actions/auth` with the `github` pool/provider). Do not reintroduce `credentials_json` / `GCP_SA_KEY`. Hub CD is push-to-`main` (path-filtered); `workflow_dispatch` remains for rollback.
- Hub entrypoint must `export HOSTNAME=0.0.0.0` (not `${HOSTNAME:-…}`). Cloud Run sets `HOSTNAME` to the instance id; Next standalone binds on that var and dies with `getaddrinfo EAI_AGAIN` if left alone. Public URL is `AUTH_URL` only.
- Production hub (`SJ_SYNC_ON_START=0`) must not `mkdir`/`stat`/`test` GCS FUSE mounts (`SJ_DATA_DIR` or `SJ_HUB_DIR`) before listen — a slow mount hangs the entrypoint and Cloud Run fails the port probe. GCS volume `mount-options` for gcloud must use **semicolons** (`uid=1001;gid=1001`); commas are parsed as separate volume keys.
- Hub CD push leaves volumes unchanged when **bucket** is blank (do not clear mounts). Live data: **deploy hub → workflow_dispatch → bucket=`fantasy-sports-analytics-sj-data`** (RW). Deprecated **hub_bucket** is ignored. Auto-mount on every push kept failing the Cloud Run port probe.
- Snapshot cache (Phase 5): `readJson` uses `unstable_cache` + tag `sj-snapshots` (not a process `Map`). Purge with `POST /api/revalidate` + `SJ_REVALIDATE_SECRET`; sync notifies when `SJ_REVALIDATE_URL` is set. Do not reintroduce an untagged in-process Map as the primary cache.
- Bundle budget: after `npm run build` in `apps/web`, `npm run verify:bundle-budget` gates First Load gzip sizes (CI `web` job). Override with `SJ_BUNDLE_ROUTE_BUDGET_GZ` / `SJ_BUNDLE_CHUNKS_BUDGET_GZ` if a deliberate bump is needed.
- `refresh.yml` promote needs `ffa-deployer` → `roles/storage.objectUser` on `gs://fantasy-sports-analytics-sj-data` (re-run `./scripts/setup-github-deployer.sh`). Hub only sees promoted files when deployed with the bucket mount.
- Snapshot reads: missing files (`ENOENT`) cache as `null`; corrupt JSON throws `CorruptSnapshotError` (not cached as missing) and surfaces via `error.tsx` (roadmap 3.6). Prefer `EmptyState` for intentional empties; wide tables should keep `table-cards` + `data-label` for mobile.
- Data source: the app reads `data/sj/` if present, otherwise falls back to committed `fixtures/sj/` sample snapshots — so the UI works offline with no ESPN sync. Live data requires the `sj sync` CLI with ESPN cookies (`ESPN_S2`/`ESPN_SWID`); not needed for browsing fixtures.
- Snapshot layout (schema_version 2): writers emit `{league}/{season}/manifest.json` plus per-concern files (`standings`, `rosters`, `matchups`, `draft`, `settings`, `transactions`, `free_agents`, optional `lineups` / `scoreboard`). Legacy `{league}/{season}.json` monoliths (committed fixtures) remain readable. Prefer `sj seed` / `sj sync` over hand-editing JSON. After serializer changes, run `sj regenerate-fixtures` and `sj validate-fixtures` (roadmap 2.5) — do not hand-edit `fixtures/sj/`.
- ESPN sync resilience (roadmap 2.4): `sj.sync.espn_call` retries transient network/5xx with backoff; timeouts via `SJ_ESPN_TIMEOUT` (default 30s) and `SJ_ESPN_MAX_ATTEMPTS` (default 4). `recent_activity` and `free_agents` are empty for seasons before 2019. Cap FA pull with `SJ_FREE_AGENT_SIZE` (default 50, max 150).
